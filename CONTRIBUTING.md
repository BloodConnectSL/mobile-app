# Contributing to Prana (ප්‍රාණ) Mobile App

To ensure code quality and a clear history of contributions, we have strict rules regarding how changes are made to the codebase. 

## 1. Branching Rules
- **No Direct Commits to `main`**: Nobody is allowed to push changes directly to the `main` branch. This includes team leads.
- **Create a Separate Branch**: For every new feature, bug fix, or task, you must create a new separate branch from `main`.
  - Recommended naming convention: `feature/your-name/your-feature-name` or `bugfix/your-name/issue-name` (e.g., `feature/nipuna/setup-docs`).

## 2. Pull Requests (PRs)
- Once your work is ready, push your branch and open a **Pull Request (PR)** against the `main` branch.
- Provide a clear description of what the PR accomplishes.

## 3. Code Reviews
- **Mandatory Reviews**: Every PR must be reviewed before it can be merged.
- **Reviewers**: Only the team leads, **Nipuna Lakruwan** and **Vimukthi Fernando**, will review and merge PRs into the main codebase.
- Address any feedback or changes requested by the leads during the review process.
